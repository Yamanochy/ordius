# Серверная часть Ordius (PocketBase)

| Папка | Что | Куда попадает на сервере |
|---|---|---|
| `pb_migrations/` | схема базы и настройки PocketBase — JS-миграции, применяются сами при запуске | `/opt/ordius/pb_migrations` |
| `pb_hooks/` | серверная логика: расчёт смен, вступление в компанию, защита владельца, журнал (`*.pb.js`, помощники в `lib/`) | `/opt/ordius/pb_hooks` |
| `test/` | автотесты: `calc.test.mjs` — расчёт денег, `api.test.mjs` — правила доступа на настоящем PocketBase | не выкладывается |

Выкладка — `ordius-deploy` на сервере (см. `server/README.md`).

## Модель данных

Всё, кроме пользователей, принадлежит компании (поле `company`). Человек видит данные компании,
только пока его участие в ней активно, и в пределах своих ролей.

| Коллекция | Что хранит |
|---|---|
| `users` | аккаунт: имя и подтверждённый звонком телефон (`+7…`, вход по нему), почта — по желанию. Телефон видит только сам человек. Какую редакцию условий использования принял и когда (`terms_version`, `terms_at`) — ставит сервер |
| `phone_checks` | проверки номера: способ, цель, попытки, билет; только для сервера, хранится 30 дней |
| `companies` | компания: название, ИНН, код вступления, тариф (тариф меняет только администратор сервера); принятая создателем редакция условий с поручением на обработку данных работников (`terms_version`, `terms_at`, ставит сервер); ставки «на руки» или до НДФЛ (`rates_basis`), суточные без НДФЛ в день (`per_diem_free_kop`, пусто — 700 ₽) |
| `memberships` | участие человека в компании: роли, статус (заявка / работает / уволен), табельный №, личный код приглашения, «НДФЛ не удерживается» (самозанятый, ИП) |
| `vehicles` | техника; нормы расхода (л/100 км, л/моточас) и текущие показания одометра и моточасов — их поднимает сервер по путевым, заправкам и ТО (скачок больше 30 000 км или 3 000 моточасов считается опечаткой) |
| `customers`, `sites` | заказчики, объекты (с координатами); объект можно привязать к контракту |
| `contracts` | контракт с заказчиком: номер, дата, предмет, срок, цена контракта (лимит). Видят владелец, руководитель, бухгалтер, диспетчер |
| `contract_items` | позиции контракта: «подметальная машина, час», «погрузчик, смена», «вывоз снега, т·км», «дежурство, месяц». Можно привязать к конкретной машине или к виду техники. Цен здесь нет — позиции видят все, водитель выбирает из них |
| `contract_prices` | цена позиции с НДС и ставка НДС (без НДС, 0, 5, 7, 10, 20, 22 %), действует с даты. Видят только владелец, руководитель, бухгалтер |
| `shift_bills` | выручка подтверждённой смены по контракту: строки, сумма, «не выставлено» с причиной. Пишет только сервер, видят те же, кто видит цены |
| `rates` | ставки людям: час, смена, рейс, т·км, км, п.м., м², м³, тонна, штука, оклад в месяц, суточные за день вахты (`per_diem`). Действуют с даты; можно привязать к водителю, технике, объекту, заказчику — самая точная побеждает |
| `rate_factors` | коэффициенты: ночь, праздник, переработка (в тысячных: 1500 = ×1,5) |
| `shifts`, `shift_entries` | смена и её строки (техника, единица, количество, позиция контракта; если заказчику выставляется в других единицах, чем платится водителю, — `bill_qty`). Сумма людям и выручка считаются сервером при подтверждении и замораживаются. Для ЭПЛ: время медосмотра, выезда и возврата, № путевого, техосмотр, одометр, моточасы, топливо на выезде/возврате и заправка |
| `adjustments` | премии (+), удержания (−) и компенсация дороги на вахту (`travel`, без НДФЛ) |
| `payouts` | авансы и выплаты; получатель может только отметить «получил» |
| `tasks`, `task_events` | задачи (поломка, запчасть, документ, ТО) и их история; статусы и назначения пишет сервер |
| `posts` | объявления для компании, можно со сроком показа (`until`) |
| `fuel_cards` | топливные карты: номер, оператор, машина, за кем закреплена, лимит. ПИН хранится зашифрованным и выдаётся отдельным запросом с записью в журнал |
| `fuel_logs` | заправки: машина, кто, карта, литры, сумма, источник (карта, наличные, своя ёмкость), показания, фото чека. Водитель вносит только свои и правит их сутки; видят офис, механик и сам водитель |
| `maintenance_plans` | план ТО машины: каждые N км, моточасов или дней; последнее выполнение. Когда осталось ≤10 % интервала, сервер ставит задачу механику, просрочено — поднимает приоритет |
| `maintenance_logs` | журнал ТО и ремонтов с затратами; запись по плану сдвигает план и закрывает задачу. Видят офис и механик |
| `rotations` | график вахт: кто, на каком объекте, с какого по какое число; вахты одного человека не накладываются. Суточные идут за дни вахт «идёт» (по сегодня) и «закончена» |
| `messages` | чат бригады (по объекту) и переписка по смене; смену видят водитель смены и офис |
| `documents` | фото путевых, ТТН, актов, чеков, а также ЭПЛ и ЭТрН (номер, дата, номер и статус в ГИС ЭПД — на будущее); файлы закрыты, скачиваются по временному токену |
| `audit_log` | журнал изменений денег, смен и участников; видят владелец и руководитель |
| `connect_codes` | коды подключения: на пилоте компанию создаёт только тот, кому администратор Ordius выдал код (кому, сколько компаний, до какого числа, сколько использовано). Правил доступа нет — только через `/api/ordius/connect-codes`; у компании хранится, по какому коду она подключилась (`connect_code`) |
| `leads` | заявки с формы на ordius.ru: имя, телефон, компания, техника, способ учёта, комментарий, редакция и время согласия. Правил доступа нет — только администратор сервера; старше года удаляются сами |

Роли: `owner` владелец, `manager` руководитель, `dispatcher` диспетчер, `mechanic` механик,
`driver` водитель, `accountant` бухгалтер. У человека может быть несколько ролей.

Свои маршруты API (`/api/ordius/…`):
- `POST phone/start {phone, purpose, method?}` — подтверждение номера через SMS.ru; только российские мобильные `+79…`;
  `purpose`: `signup`, `login`, `reset`, `change`. Лимиты: 3 проверки на номер в час и 6 в сутки,
  20 в час с одного адреса, 300 в сутки на весь сервис. Два способа:
  - `callcheck` (по умолчанию): ответ — номер, на который человек звонит сам (бесплатно, звонок сбрасывается),
    и билет; `POST phone/status {check}` раз в 2–3 секунды → `waiting` / `verified` / `expired`, 5 минут на звонок;
  - `call` (запасной, SMS.ru пометил его устаревшим): робот звонит человеку, тот вводит последние 4 цифры
    входящего номера в `POST phone/verify {check, code}` → билет, 5 попыток;
  билет действует 15 минут после подтверждения и один раз;
- `POST signup {ticket, name, password, terms}` — регистрация (только так, напрямую в `users` нельзя), сразу вход;
  `terms` — редакция условий использования, которую человек принял (`lib/legal.js`); старая или пустая — отказ.
  Создание компании тоже требует `terms` в теле запроса: создатель принимает условия с поручением на обработку данных работников;
- `POST phone/login {ticket}` — вход без пароля; `POST phone/change {ticket}` — смена номера;
- `GET invitations`, `POST invitations/{id}/accept` — руководитель завёл человека с телефоном, человек принимает сам;
- `POST join {code}` — вступить по коду компании (заявка) или по личному приглашению (сразу в работу);
- `POST memberships/{id}/invite` — личный код на 7 дней для заведённого человека;
- `POST companies/{id}/join-code` — новый код вступления, старый перестаёт работать;
- `POST memberships/{id}/password-code` — одноразовый код смены пароля на сутки для сотрудника без почты
  (не владельцу; руководителю — только от владельца; не тому, кто состоит ещё в другой компании);
- `POST password-reset {ticket, password}` или `{phone, code, password}` — новый пароль по звонку или по коду
  руководителя, прежние входы сбрасываются;
- `GET payroll?company&from&to[&member][&format=csv]` — ведомость за период, CSV для бухгалтерии: смены, оклад, премии,
  дни вахты и суточные, дорога, удержания, начислено до НДФЛ, НДФЛ, на руки, выплачено, к выплате.
  НДФЛ — для резидентов по прогрессивной шкале (13 % до 2,4 млн ₽ в год, дальше 15 %…), нарастающим итогом с начала года,
  в полных рублях. Ставки «на руки» — налог сверху; до НДФЛ — удерживается. Суточные до лимита и дорога — без НДФЛ;
- `GET registry?company&contract&from&to[&format=csv]` — реестр выполненных работ по контракту для акта и сверки:
  строки по сменам (дата, объект, техника, водитель, позиция, количество, цена, сумма, НДС), итоги по позициям,
  абонентские позиции «в месяц» пропорционально дням, «не выставлено» с причинами, выполнено за всё время против цены контракта;
- `GET revenue?company&from&to&group=customer|contract|site|vehicle` — выручка, оплата людям и разница;
- `POST bills/recalc {company, from, to}` — пересчитать выручку подтверждённых смен (после того как внесли цену; владелец и руководитель);
- `POST fuel-cards/{id}/pin {pin}` — задать ПИН (4–8 цифр, владелец и руководитель); `GET fuel-cards/{id}/pin` —
  показать (руководство и тот, за кем карта), каждый просмотр — в журнале;
- `GET fuel?company&from&to[&vehicle][&format=csv]` — ГСМ по машинам: км и моточасы по путевым, расход против нормы,
  заправлено по чекам и картам против записанного в путевых (офис и механик);
- `GET maintenance?company` — состояние ТО по всем машинам (офис и механик); `POST maintenance/sync {company}` — проверить
  сроки сейчас (иначе раз в час по расписанию);
- `GET me` — `{platform_admin, company_code_required}`: администратор ли человек (номер в `ORDIUS_ADMIN_PHONES` на сервере)
  и нужен ли ему код, чтобы создать компанию; `GET connect-codes`, `POST connect-codes {note, max_uses?, days?}`,
  `POST connect-codes/{id}/revoke` — коды подключения, только администратор. Компания создаётся обычным запросом
  с кодом в поле тела `connect_key`; без кода — отказ, пока не задано `ORDIUS_OPEN_COMPANIES=1`.
  Попыток создать компанию — не больше 10 за 10 минут с одного адреса;
- `POST lead` — заявка с формы на ordius.ru (вместо облачной функции Yandex Cloud из `form/`): только со страниц ordius.ru
  (`ORDIUS_LEAD_ORIGINS` — другой список), ловушка для ботов и проверка полей как в `form/index.js`, 10 заявок за 10 минут
  с одного адреса. Если в PocketBase включена почта (SMTP), карточка заявки приходит на адрес отправителя
  (`ORDIUS_LEADS_TO` — другой); без почты заявка всё равно сохраняется.

Офлайн: приложение само задаёт `id` новой записи (15 символов `a-z0-9`) и при повторной отправке получает отказ
«уже есть» вместо дубля — так смены и фото, внесённые без связи, догружаются безопасно.

Как считается выручка смены: для каждой строки берётся позиция контракта — указанная в строке, иначе позиция
с той же единицей: сначала для этой машины, потом для её вида техники, потом общая; если подходят несколько
равных — просим выбрать позицию в строке. Цена — действующая на дату смены.
Нет позиции или цены — смена всё равно подтверждается, а выручка помечается «не выставлено» с причиной;
после исправления — `bills/recalc`.

## Правила
- схему меняем только миграциями из репозитория, не руками в панели;
- уже выложенную миграцию не правим — пишем новую;
- деньги храним в копейках целыми числами, ставки — записями «действует с даты»;
- поле, от которого зависит доступ, проверяется в правиле коллекции, а не только в хуке
  (правила PocketBase проверяются раньше хуков);
- в хуке обработчик передаётся напрямую: переменные верхнего уровня файла внутри обработчика не видны,
  помощники подключаются через `require` внутри него;
- `hidden`-поля PocketBase не принимает от клиента — их ставит только сервер;
- JSON-поле в хуке читать через `jsonOf(record, "поле", запасное)` из `lib/util.js`: `record.get()` отдаёт сырые байты;
- модулю из `lib/` другой модуль передаётся параметром (`fleet.syncMaintenanceTasks(app, calc, …)`), а не через `require` внутри;
- цены заказчика и выручку не класть в записи, которые видит водитель, — только в `contract_prices` и `shift_bills`.

## Тесты

```bash
node backend/test/calc.test.mjs
PB_BIN=/путь/к/pocketbase node backend/test/api.test.mjs
```

`api.test.mjs` поднимает PocketBase во временной папке с миграциями и хуками из репозитория и проходит
сценарий двух компаний: регистрация по телефону, вступление, смены и их подтверждение с расчётом,
выплаты, ведомость с суточными и НДФЛ, контракты и выручка, реестр, топливные карты, заправки и ГСМ, ТО с задачами
механику, вахты, чат, офлайн-догрузка, документы, задачи —
и что чужие данные не видны и не меняются, а водитель не видит цен заказчика.
В GitHub это делает `.github/workflows/backend-tests.yml` на каждое изменение `backend/`.
