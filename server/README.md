# Сервер Ordius

Рабочая версия Ordius живёт на одном сервере в России. Копии каждый час уходят в хранилище другой
компании в другом городе.

| Что | Где |
|---|---|
| Сервер | Timeweb Cloud, Новосибирск, `ordius-app`, 201.24.62.222, Ubuntu 24.04, 1 ядро / 1 ГБ / 15 ГБ |
| Приложение и API | https://app.ordius.ru |
| Копии | Beget S3, Санкт-Петербург, `s3.ru1.storage.beget.cloud`, бакет `60e78ff966f3-ordius-backup-640466` |
| Лендинг | ordius.ru — GitHub Pages, к серверу не относится |

```
телефон / ПК ──HTTPS──▶ Caddy :443 ──▶ PocketBase 127.0.0.1:8090 ──▶ /var/lib/ordius/pb_data
                                                  │                    (data.db + storage/)
                        ordius-backup (каждый час)┴──restic, шифрование──▶ Beget S3 (Санкт-Петербург)
```

- **Caddy** — HTTPS, сертификат Let's Encrypt выпускается и продлевается сам. Закрывает снаружи
  панель администратора и служебные разделы API. Журнал запросов с IP-адресами не ведёт.
- **PocketBase** — база (SQLite), вход пользователей, правила доступа, файлы, живые обновления.
  Слушает только 127.0.0.1, работает от отдельного пользователя `pocketbase` с ограниченными правами.
- **restic** — зашифрованные копии. Передаёт только изменения, поэтому фото уходят один раз.

## Установка с нуля

Подготовка (ключ SSH, сервер, бакет, DNS) — в документе «Сервер Ordius — по шагам».
Затем одна команда в PowerShell на своём компьютере:

```powershell
ssh -t root@201.24.62.222 "curl -fsSL https://raw.githubusercontent.com/Yamanochy/ordius/main/server/setup.sh -o /root/ordius-setup.sh && bash /root/ordius-setup.sh --domain app.ordius.ru --endpoint s3.ru1.storage.beget.cloud --bucket 60e78ff966f3-ordius-backup-640466"
```

Хранилище копий может быть любым S3-совместимым в России: `--endpoint` — его адрес, `--bucket` — имя бакета.
Для Selectel вместо `--endpoint` можно указать `--pool ru-7`. Регион подписи и стиль адресации скрипт
подбирает сам и записывает в `/etc/ordius/ordius.conf`.

Скрипт:
1. ставит обновления, межсетевой экран (открыты 22, 80, 443), автообновления безопасности;
2. отключает вход по паролю — только по SSH-ключу;
3. ставит Caddy и PocketBase (версия закреплена в `setup.sh`, контрольная сумма проверяется);
4. спрашивает **Access key** и **Secret key** хранилища копий — вставить из панели хранилища;
5. показывает **пароль шифрования копий** и **пароль администратора** — сохранить сразу;
6. делает первую копию и пробное восстановление.

Повторный запуск безопасен: пароли и ключи не пересоздаются.

## Пароли и ключи

| Что | Где хранится | Если потерять |
|---|---|---|
| Пароль шифрования копий | менеджер паролей + бумага; на сервере `/etc/ordius/restic.pass` | Сервер пропадёт — копии не открыть. **Самое важное.** |
| Пароль администратора PocketBase | менеджер паролей | Сбросить на сервере командой ниже |
| Ключи хранилища копий | панель Beget (Облако → Ordius backup → Реквизиты доступа); на сервере `/etc/ordius/backup.env` | Посмотреть в панели Beget |
| Ключ шифрования настроек PocketBase | `/etc/ordius/pocketbase.env`, входит в копии | Восстанавливается вместе с копией |
| SSH-ключ | только на твоём компьютере, `~/.ssh/id_ed25519` | Добавить новый ключ через панель Beget |

Сброс пароля администратора:

```bash
runuser -u pocketbase -- env $(cat /etc/ordius/pocketbase.env) \
  /opt/ordius/pocketbase/pocketbase superuser update ordius.info@yandex.ru НОВЫЙ_ПАРОЛЬ \
  --dir=/var/lib/ordius/pb_data --migrationsDir=/opt/ordius/pb_migrations \
  --hooksDir=/opt/ordius/pb_hooks --encryptionEnv=PB_ENCRYPTION_KEY
```

## Каждый день

Ничего делать не нужно. Проверить состояние:

```bash
ssh root@IP
ordius-status
```

## Панель администратора PocketBase

Из интернета панель закрыта. Вход — через SSH-туннель:

1. В PowerShell: `ssh -N -L 8090:127.0.0.1:8090 root@IP` — окно оставить открытым.
2. В браузере: http://127.0.0.1:8090/_/ — почта ordius.info@yandex.ru и пароль администратора.

Даже с паролем администратора войти в панель можно только с самого сервера: PocketBase проверяет IP
(настройка в `backend/pb_migrations/…_ordius_settings.js`).

## Копии

| | |
|---|---|
| Что входит | снимок базы, все файлы и фото, ключ шифрования настроек |
| Как часто | каждый час (`ordius-backup.timer`) |
| Сколько хранятся | 48 почасовых и 21 ежедневная; если хранилище поддерживает версии — прежние версии ещё 7 дней. Данные удалённого человека исчезают из копий не позже чем через 30 дней (ч. 5 ст. 21 152-ФЗ) |
| Проверка | каждую ночь — удаление старых; по воскресеньям — проверка хранилища и пробное восстановление |

Вручную: `ordius-backup` — сделать копию сейчас; `ordius-maintain --test` — пробное восстановление.

Оповещение, если копия не сделалась: завести бесплатную проверку на healthchecks.io с интервалом
1 час, вписать её адрес в `/etc/ordius/ordius.conf` строкой `HEALTHCHECK_URL=https://hc-ping.com/…`.
Туда уходит только «копия сделана / не сделана», без данных.

## Восстановление

**Откатить данные на этом же сервере** (например, после ошибочного удаления):

```bash
ordius-restore --list        # список копий с датой и временем (UTC)
ordius-restore 1a2b3c4d      # восстановить нужную; или: ordius-restore latest
```

Текущие данные не удаляются, а переносятся в `/var/lib/ordius/pb_data.before-restore-<время>`.
Когда убедились, что всё в порядке, удалите эту папку: в ней персональные данные.

**Сервер пропал** — новый сервер за ~30 минут:

1. Создать новый сервер (Timeweb, Beget или другой российский провайдер) с Ubuntu 24.04 и своим SSH-ключом.
2. Поменять A-запись `app` в DNS на новый IP.
3. Запустить ту же команду установки (с новым IP), добавив `--restore`. Скрипт спросит ключи хранилища и пароль
   шифрования копий, скачает последнюю копию и запустит сервис.

**Учения** — раз в квартал проверить, что из копии сервер реально поднимается, не трогая рабочий:

1. Создать временный сервер (Ubuntu 24.04, свой SSH-ключ), DNS не менять.
2. Запустить команду установки с новым IP, `--domain drill.ordius.ru` и `--drill` вместо `--restore`.
   Скрипт спросит ключи хранилища и пароль копий, восстановит последнюю копию и покажет, что в ней.
   Копий с временного сервера не делает: они смешались бы с рабочими (имя хоста у всех копий одно).
3. Удалить временный сервер в панели — на нём копия рабочих данных.

## Выкладка новой версии

```bash
ordius-deploy
```

Делает копию, берёт ветку `main` из GitHub, раскладывает `backend/pb_migrations`, `backend/pb_hooks`,
`app/dist` и перезапускает PocketBase. Миграции базы применяются при запуске. Если сервис не поднялся —
скрипт скажет, что делать.

## Обновление PocketBase

Раз в месяц, после чтения [списка изменений](https://github.com/pocketbase/pocketbase/releases):

```bash
ordius-pb-update 0.40.6
```

Копия до обновления, при сбое запуска — возврат прежней версии. Обновления Ubuntu и Caddy ставятся
сами; если нужна перезагрузка, она происходит в 04:00 по Новосибирску.

## Где что лежит

| Путь | Что |
|---|---|
| `/var/lib/ordius/pb_data` | база `data.db` и файлы `storage/` |
| `/var/lib/ordius/backup` | последний снимок базы и отметка `last-ok` |
| `/etc/ordius` | настройки и секреты (доступ только root) |
| `/opt/ordius/repo` | клон репозитория для выкладки |
| `/opt/ordius/pocketbase` | версии PocketBase, ссылка `pocketbase` — текущая |
| `/etc/caddy/Caddyfile` | настройки HTTPS (из `server/config/Caddyfile`) |
| `journalctl -u ordius-pocketbase` | журнал PocketBase |
| `journalctl -u ordius-backup` | журнал копий |

## Проверка скриптов

```bash
bash server/test/test.sh
```

Без настоящего сервера: вместо хранилища копий — локальный S3 (moto), вместо PocketBase — тестовая база.
Проверяет копию, пробное и настоящее восстановление, откат на раннюю копию, сбой хранилища
с оповещением, выкладку. Нужны `restic sqlite3 rsync git shellcheck` и `pip install "moto[server]" boto3`.
