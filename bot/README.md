# Бот Ordius — @Ordius_app_bot

> **Отложен (17.10.2026).** С весны 2026 года многие российские хостинги блокируют связь с Telegram API
> в обе стороны, а Yandex Cloud с 11.10.2026 в аварийном режиме. Заявки на пилот принимает форма на сайте —
> см. `form/README.md`. Код бота рабочий и проверен; вернёмся к нему, когда прояснится ситуация с Telegram,
> или переделаем под MAX (нужны ИП или юрлицо).

Заявки на пилот и вопросы клиентов. Облачная функция Yandex Cloud по вебхуку Telegram.
Один файл `index.js`, без сторонних библиотек. Логика не привязана к Telegram — можно будет подключить к MAX.

## Где живут персональные данные

| Что | Куда |
|---|---|
| Запись заявки, номера, вопроса | Бакет Object Storage в России (ч. 5 ст. 18 152-ФЗ) |
| Полная карточка с контактами | Письмом на ordius.info@yandex.ru (Яндекс Почта, Россия) |
| Оповещение администратору | Telegram — **только номер обращения** (#K7M2QX) и ответы про технику, без имени, ника, id, телефона и текста |

Поэтому трансграничной передачи нет, и отдельное уведомление в Роскомнадзор о ней не нужно.

## Что умеет

- `/start` — приветствие и меню: демо, запись на пилот, тарифы, вопрос, сайт.
- Запись на пилот: сколько техники → как ведут учёт → номер кнопкой «Отправить номер»
  (со ссылками на согласие и политику). Приходят два письма (заявка, номер) и два оповещения в Telegram.
- Любой текст от клиента — вопрос: письмо с текстом и контактами + оповещение в Telegram.
- Ответ клиенту: в чате с ботом сделать «Ответить» на оповещение с номером обращения и написать текст —
  бот найдёт клиента в хранилище и перешлёт ответ. Нажатие на `#номер` в Telegram покажет всю историю обращения.
- `/id` — показывает chat id (нужен для настройки).
- Если запись в хранилище или письмо не прошли, в оповещении будет «⚠️» с подсказкой.

Проверка логики: `node bot/test.js` (39 проверок, включая отправку письма по TLS на тестовый SMTP-сервер).

## Запуск

Перед запуском: опубликованы `privacy.html` и `consent.html` (готово) и подано уведомление в Роскомнадзор.

### 1. Почта ordius.info@yandex.ru — пароль приложения
1. Войти в ящик ordius.info@yandex.ru → шестерёнка «Настройки» → «Все настройки» → **«Почтовые программы»**.
2. Включить «С сервера imap.yandex.ru по протоколу IMAP» и проверить, что отмечено «Пароли приложений и OAuth-токены» → «Сохранить изменения».
3. Открыть id.yandex.ru → «Безопасность» → **«Пароли приложений»** → в строке «Почта» нажать «+».
4. Название: `Бот Ordius` → «Далее» → скопировать пароль. Он показывается один раз — сразу вставьте его
   в переменную `MAIL_PASS` (шаг 4) или временно в заметку, которую потом удалите. Никому его не пересылайте.

### 2. Аккаунт и бакет в Yandex Cloud
1. console.yandex.cloud → войти через Яндекс ID → создать платёжный аккаунт (физлицо, карта).
   При наших объёмах хватает бесплатного уровня.
2. Слева «Object Storage» → «Создать бакет». Имя: `ordius-leads-` + несколько случайных цифр.
   Доступ на чтение объектов, к списку объектов и к настройкам — **«Ограниченный»**. Класс — «Стандартное» → «Создать бакет».
3. Открыть бакет → «Жизненный цикл» → «Настроить» → «Добавить правило»: префикс **оставить пустым**
   (правило на весь бакет), удаление объектов через `365` дней → «Сохранить». Это срок хранения из политики.

### 3. Сервисный аккаунт
«Identity and Access Management» → «Сервисные аккаунты» → «Создать сервисный аккаунт» →
имя `ordius-bot`, роль **`storage.uploader`** (запись и чтение бакета) → «Создать».

### 4. Функция
1. «Cloud Functions» → «Создать функцию» → имя `ordius-bot` → «Создать».
2. «Редактор»: среда **Node.js 22** → «Продолжить». Способ — «Редактор кода», в `index.js` вставить содержимое `bot/index.js`.
3. Точка входа `index.handler`, таймаут **`15`** с, память `128 МБ`, **сервисный аккаунт — `ordius-bot`**.
4. «Переменные окружения»:
   - `BOT_TOKEN` — токен от @BotFather (перед этим `/revoke` → новый токен);
   - `WEBHOOK_SECRET` — 30–40 случайных латинских букв и цифр (из генератора паролей);
   - `BUCKET` — имя бакета из шага 2;
   - `MAIL_USER` — `ordius.info@yandex.ru`;
   - `MAIL_PASS` — пароль приложения из шага 1.
   `ADMIN_CHAT_ID` пока не добавлять → «Сохранить изменения».
5. «Обзор» → включить «Публичная функция» → скопировать «Ссылку для вызова» (`https://functions.yandexcloud.net/d4e…`).

### 5. Вебхук и проверка
1. В браузере открыть (свои значения, без пробелов):
   `https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<ССЫЛКА_ФУНКЦИИ>&secret_token=<WEBHOOK_SECRET>&drop_pending_updates=true`
   → должно быть `{"ok":true,"result":true,"description":"Webhook was set"}`.
2. Написать боту `/id` → он пришлёт число. В «Редакторе» функции добавить `ADMIN_CHAT_ID` с этим числом → «Сохранить изменения».
3. С **другого** аккаунта Telegram (жены, второго телефона): `/start` → «Записаться на пилот» → до конца.
   Проверить: в ваш чат с ботом пришли оповещения с `#номером` без имени и телефона; на почту — два письма
   с карточкой; в бакете появились папки `records/`, `refs/`, `pending/`.
4. С того же аккаунта задать вопрос → у себя сделать «Ответить» на оповещение → ответ должен прийти клиенту.

## Если что-то не работает

- Бот молчит: «Логи» функции; вебхук — `https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo` (поле `last_error_message`).
- `403` — `secret_token` в вебхуке не совпадает с `WEBHOOK_SECRET`. `500 not configured` — нет `BOT_TOKEN` или `WEBHOOK_SECRET`.
- «⚠️ Не записано в хранилище»: в логах `BUCKET not set` — нет переменной; `no IAM token` — не выбран сервисный аккаунт;
  `storage put error 403` — у аккаунта нет роли `storage.uploader`.
- «⚠️ Письмо не отправлено»: `SMTP AUTH: 535` — неверный пароль приложения или не включён доступ почтовых программ (шаг 1);
  `SMTP timeout` — повторить позже, данные уже в хранилище.
