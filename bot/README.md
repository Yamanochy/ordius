# Бот Ordius — @Ordius_app_bot

Заявки на пилот и вопросы клиентов. Работает как облачная функция Yandex Cloud
по вебхуку Telegram. Каждая заявка, номер и вопрос сначала записываются в бакет
Object Storage в России (локализация по ч. 5 ст. 18 152-ФЗ), потом копия приходит
администратору в Telegram. Код логики не привязан к Telegram — его можно будет подключить к MAX.

Файлы: `index.js` — сам бот, `test.js` — проверка логики (`node bot/test.js`).

## Что умеет

- `/start` — приветствие и меню: демо, запись на пилот, тарифы, вопрос, сайт.
- Запись на пилот: сколько техники → как ведут учёт → номер кнопкой «Отправить номер»
  (со ссылкой на согласие и политику). Администратору приходят две карточки: ответы и номер.
- Любой текст от клиента — вопрос администратору с меткой `#u<id>`. Чтобы ответить,
  администратор делает «Ответить» на это сообщение — ответ уходит клиенту.
- `/id` — показывает chat id (нужен для настройки).
- Если запись в хранилище не удалась, в карточке администратора будет «⚠️ Не записано в хранилище».

## Запуск в Yandex Cloud

Перед запуском: опубликовать `privacy.html` и `consent.html` и подать уведомление
в Роскомнадзор — бот собирает телефоны.

### 1. Аккаунт
console.yandex.cloud → войти через Яндекс ID → создать платёжный аккаунт
(физлицо, карта). Без него функции не работают; при наших объёмах хватает бесплатного уровня.

### 2. Бакет для заявок
1. Слева «Object Storage» → «Создать бакет».
2. Имя: `ordius-leads-` + несколько случайных цифр (имя должно быть уникальным во всём Yandex Cloud).
3. Доступ на чтение объектов, к списку объектов и к настройкам — **«Ограниченный»**. Класс — «Стандартное». Размер можно не ограничивать → «Создать бакет».
4. Открыть бакет → «Жизненный цикл» → «Настроить» → «Добавить правило»: префикс `leads/`,
   «Удаление объектов» через `365` дней → «Сохранить». Это срок хранения из политики.

### 3. Сервисный аккаунт
1. Слева «Identity and Access Management» → «Сервисные аккаунты» → «Создать сервисный аккаунт».
2. Имя `ordius-bot`, роль — `storage.uploader` → «Создать».

### 4. Функция
1. Слева «Cloud Functions» → «Создать функцию» → имя `ordius-bot` → «Создать».
2. Вкладка «Редактор»: среда выполнения **Node.js 22** → «Продолжить».
   Способ — «Редактор кода», файл `index.js` — вставить содержимое `bot/index.js`.
3. Ниже: точка входа `index.handler`, таймаут `10` с, память `128 МБ`,
   **сервисный аккаунт — `ordius-bot`**.
4. «Переменные окружения» → добавить:
   - `BOT_TOKEN` — токен от @BotFather (перед этим сделать новый: `/revoke`);
   - `WEBHOOK_SECRET` — 30–40 случайных латинских букв и цифр (из генератора паролей);
   - `BUCKET` — имя бакета из шага 2.
   `ADMIN_CHAT_ID` пока не добавлять. Нажать «Сохранить изменения».
5. Вкладка «Обзор» → включить переключатель «Публичная функция».
   Скопировать «Ссылку для вызова» вида `https://functions.yandexcloud.net/d4e…`.

### 5. Вебхук и проверка
1. В браузере открыть адрес (подставив свои значения, без пробелов):
   `https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<ССЫЛКА_ФУНКЦИИ>&secret_token=<WEBHOOK_SECRET>&drop_pending_updates=true`
   Должно показать `{"ok":true,"result":true,"description":"Webhook was set"}`.
2. В Telegram написать боту `/id` — он пришлёт число. Вернуться в «Редактор» функции,
   добавить переменную `ADMIN_CHAT_ID` с этим числом → «Сохранить изменения».
3. `/start` → «Записаться на пилот» → пройти до конца. Карточки заявки должны прийти
   в этот же чат с ботом без значка ⚠️, а в бакете появиться папка `leads/<дата>/` с файлами.

## Если что-то не работает

- Бот молчит: «Логи» функции в консоли Yandex Cloud; проверить вебхук —
  `https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo` (поле `last_error_message`).
- `403` в логах — `secret_token` в вебхуке не совпадает с `WEBHOOK_SECRET`.
- `500 not configured` — не заданы `BOT_TOKEN` или `WEBHOOK_SECRET`.
- В карточке «⚠️ Не записано в хранилище»: в логах `BUCKET not set` — нет переменной;
  `no IAM token` — у функции не выбран сервисный аккаунт; `storage error 403` — у аккаунта нет роли `storage.uploader`.
